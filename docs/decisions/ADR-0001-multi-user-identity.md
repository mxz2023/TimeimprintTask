# ADR-0001 · 多用户账号与会话身份

| 项目 | 值 |
| --- | --- |
| 编号 | ADR-0001 |
| 标题 | 只保留账号登录，覆盖本地开发与测试 |
| 状态 | ACCEPTED |
| 提出阶段 | [P06](../phases/P06/README.md) |
| 日期 | 2026-10-10 |
| 修订 | 2026-10-10：按用户口径去掉固定身份和调试头；注册须短信验证；登录包含手机号密码与微信，并为飞书等扫码留扩展 |

用户于 2026-10-10 接受本决策。执行规则以已经回写的 [01](../01-MVP-SPEC.md)—[07](../07-ACCEPTANCE.md) 为准。本文保留理由，不单独授权编码；编码仍须 [P06](../phases/P06/README.md) 获得实施授权。

行为参照 TimeImprintServer 的 Django 账号实现（`apps/accounts`）：短信验证码、手机号注册、手机号密码登录、微信身份的查找或创建、绑定与解绑、绑定手机号时按验证码合并账号。不把 Django 源码中的腾讯云应用号、签名、模板或密钥抄进仓库。

## 1. 当前问题

平台公开接口靠 local profile 的固定 actor（操作者）或 test profile 的 `X-Debug-Actor-Id`（调试身份头）决定 `ActorContext`（当前操作者上下文）。请求不能注册新用户，本地开发者和测试也不能用真实登录区分身份。

用户要求以后只有一种登录：多用户账号。本地开发用本地开发账号，自动化测试用测试账号，差别在账号，不在另一套身份开关。注册必须先通过手机短信验证。登录方式包括手机号加密码，以及微信第三方登录；飞书等扫码登录以后要能接上，本期不实现。

## 2. 保持现有设计的后果

固定身份和调试头继续存在时，同一进程里可以不登录就调用任务接口。这和「只有账号登录」冲突，也不能证明短信注册、微信绑定和跨账号隔离。

## 3. 未采用的替代

保留 local 固定身份和 test 调试头，另加一套可选的 `users` profile。未采用原因：用户明确要求未来不再保留这两种身份形式，本地和测试都以账号区分。

## 4. 决策

下列条款已接受。

1. **身份只有账号。** 删除固定 `ActorContextProvider`（当前操作者上下文提供器）和测试调试头。公开任务接口必须带会话令牌。无令牌、坏令牌或停用账号返回 `UNAUTHENTICATED`。请求体不得自报 userId。`actorId` 等于用户 id。tenant 仍是配置中的单一 tenant，本期不做多租户。
2. **环境差在账号和数据，不在身份开关。** 现有 local、test 若仍表示数据库、端口和监听地址，可以保留这些运行配置。它们不再切换身份实现。本地库预置或由开发者注册的是本地开发账号；测试库预置测试账号。测试先登录拿到令牌，再调用任务接口。跨用户用例登录两个测试账号，不再使用调试头。
3. **注册。** 先向手机号发送短信验证码，校验通过后才能用手机号、验证码、密码和可选昵称注册。验证码约 10 分钟内有效，错误或过期拒绝注册。已注册手机号拒绝再次注册。密码只存摘要。
4. **短信。** 发送语义对齐 Django：生成验证码，通道成功后才入库；失败不把验证码交给调用方。正式通道使用腾讯云短信，密钥、应用号、签名和模板只来自环境变量。自动化测试使用不访问外网的替身，把验证码留在测试可读的记录里。仓库不存放真实密钥。
5. **手机号密码登录。** 校验手机号和密码。成功后的登录结果对齐 Django：若该账号尚未完成一次性授权，返回短时 challenge（挑战）且不签发业务令牌；授权字符串校验通过后才签发令牌，并记录已授权时间。授权字符串只来自服务端环境，比较采用常量时间。未配置授权字符串时，授权步骤失败并提示联系管理员。
6. **会话。** 令牌可复用直到退出或被授权流程作废。库中只存令牌摘要，不明文落库。请求使用 `Authorization: Bearer`。退出登录作废该用户当前令牌。停用账号不能登录。
7. **微信。** 本期实现网页与移动端 code 登录：校验 state，用 code 换取身份，按 openid 查找，必要时用 unionid 兜底；没有绑定则创建用户。已登录用户可绑定或解绑。解绑前必须仍有手机号或可用密码。微信用户绑定手机号时必须先过短信验证码；手机号属于另一活跃账号时，把微信身份迁到该账号、更新密码并停用临时账号，且整段写入同一事务。同一微信不得绑到两个用户。
8. **以后的扫码登录。** 社交身份按 provider（提供方）区分。本期 provider 只实现微信。飞书及其他扫码登录只保留扩展点和契约位置，不编码、不验收。
9. **同时期的账号能力。** 对齐 Django 里已经存在、且被注册登录直接依赖的部分：校验验证码、忘记密码（短信验证码加新密码）、当前用户改密、改昵称、管理员分页查询用户。管理员列表不返回密码、令牌和第三方原始报文。空库第一个完成注册并授权的账号成为管理员。
10. **任务参与人。** OWNER 与 RECIPIENT 的 `principalId` 必须是当前 tenant 内活跃用户 id，不能再要求等于某个固定 actor。
11. **模块与表。** 新建 `timeimprint-task-identity` 保存账号、验证码、会话、社交绑定和上述事务规则，使用专有表，不改平台公共表，不改 kernel。腾讯云短信与微信 HTTP 客户端放进已有 `timeimprint-task-adapter`，identity 调用 adapter。飞书扫码客户端以后也进 adapter，本期不建。gateway 只根据令牌构造 `ActorContext`。
12. **监听地址。** 本期仍只监听回环地址。账号登录不自动把服务暴露到局域网。

## 5. 明确不做

- 本期实现飞书、钉钉或其他扫码登录。
- 多租户、团队角色、转交、代理、通知委托。
- 前端页面。
- Redis。把令牌放进数据库。
- 把 Django 文件里的短信应用号、签名、模板或密钥写入仓库。
- 改写已 RELEASED 的 P01—P05 文档。实现时会替换仍在运行的固定身份代码，并让旧测试改为登录测试账号。

## 6. 影响

| 类别 | 影响 |
| --- | --- |
| 场景 | S01/S02 状态机不变。参与人从「必须等于固定 actor」改为「必须是活跃用户」 |
| INV | 不修改 [INV-01](../02-AI-CODING-GUIDE.md)—[INV-09](../02-AI-CODING-GUIDE.md) 的条文。INV-08 仍要求身份留在外层。固定身份不再是运行时实现 |
| API | 现有任务接口改为必须登录。[A14](../07-ACCEPTANCE.md)（local 不被请求改身份）要改写成账号隔离。调试头失效 |
| 数据 | 新增身份专有表。平台公共表结构不变。已有数据里的固定 actor id 不会自动变成用户 id |
| SPI | `ActorContextProvider` 保留接口，删除固定实现和调试头实现，改为会话实现 |
| 测试 | 全部公开接口测试先用测试账号登录。短信测试不调用腾讯云 |
| 运维 | 本地开发账号与测试账号分开。短信和微信凭据缺失时，对应登录方式启动失败；未启用的飞书扫码不要求凭据 |

## 7. 接受后要改的正式契约

- [01](../01-MVP-SPEC.md)、[03](../03-INTEGRATION-CONTRACTS.md)、[04](../04-API.md)：删除固定身份和调试头作为当前运行规则，写入账号、短信、微信和令牌。
- [02](../02-AI-CODING-GUIDE.md)：模块表增加 `timeimprint-task-identity`；adapter 增加短信与微信客户端职责。
- [05](../05-DATABASE.md)：身份专有表。
- [06](../06-SCHEDULING.md)、[S01](../scenarios/S01-reminder.md)、[S02](../scenarios/S02-recurring-todo.md)：参与人改为活跃用户 id。
- [07](../07-ACCEPTANCE.md)：改写身份验收，并为短信、注册、登录、授权、微信绑定合并增加编号。
- [CAP04](../capabilities/CAP04-collaboration.md) 账号子集与 [C13](../capabilities/README.md)：达到 `READY_FOR_IMPLEMENTATION` 后，P06 才能转 READY。
- [HUMAN-GLOSSARY](../HUMAN-GLOSSARY.md)：修订固定身份释义，补验证码、社交账号和令牌。

## 8. 回滚

身份专有表一旦写入用户，不能把运行时改回固定 actor，否则历史参与人对不上。回滚手段是停用新版本并保留账号数据，不回改已执行的 Flyway 脚本。P01—P05 的 Git 标签仍指向没有账号登录的代码。
