# ADR-0002 · 正式微信扫码与小时/分钟间隔

| 项目 | 值 |
| --- | --- |
| 编号 | ADR-0002 |
| 标题 | 网页微信扫码登录，以及按小时、按分钟重复且禁止稍后 |
| 状态 | ACCEPTED |
| 提出阶段 | [P07](../phases/P07/README.md) |
| 日期 | 2026-10-11 |

用户于 2026-10-11 指定 P07：增加正式微信扫码；增加分钟和小时单位的间隔提醒；这两种间隔不支持稍后功能。执行规则以回写后的 [01](../01-MVP-SPEC.md)—[07](../07-ACCEPTANCE.md) 为准。本文保留理由，不单独授权超出 [P07](../phases/P07/README.md) 的编码。

## 1. 当前问题

[P06](../phases/P06/README.md) 的微信登录是捕获模式：`code` 被当作 openid（微信用户标识），[E25](../04-API.md)（微信登录配置）返回空的授权地址，不访问微信开放平台，因此不能扫码。

[CAL-01](../capabilities/CAP01-calendar.md)—[CAL-05](../capabilities/CAP01-calendar.md) 的重复间隔最小是一个自然日。[S02](../scenarios/S02-recurring-todo.md)（周期待办）的稍后提醒（snooze）对全部周期实例开放。

## 2. 保持现有设计的后果

没有授权地址和一次性 state（防伪随机串）时，客户端无法打开微信扫码页，回调也无法证明 code 来自本次配置请求。日历若只有「每 N 日」，不能表达「每 2 小时」或「每 15 分钟」。若这两种密间隔仍允许稍后，一次平移会把催办槽位推过下一次发生，和短周期的锚点重复冲突。

## 3. 未采用的替代

把扫码留在捕获模式，由调用方自己拼授权地址。未采用原因：state 必须由服务端签发并一次性消费，密钥不能出现在配置响应里。

把小时和分钟折算成不足 1 的 `intervalDays`。未采用原因：现有锚点按自然日对齐，不能表示日内重复，也会改变 [CAL-05](../capabilities/CAP01-calendar.md) 已发布结果。

小时和分钟实例仍保留稍后，只在文档里建议不要用。未采用原因：用户明确要求这两种间隔不支持稍后。

## 4. 决策

1. **网页扫码。** `appType=web` 且微信模式为 `live` 时，[E25](../04-API.md) 签发一次性 state，返回微信网站应用扫码地址（`qrconnect`，`scope=snsapi_login`）。state 只存摘要，10 分钟内、未消费才能用于 [E26](../04-API.md)（微信回调）或绑定。用 code 向微信换 openid，不把访问令牌写入库或错误响应。`capture` 仍把 code 当作 openid，供自动化测试使用，不得用于面向真实用户的部署。`ios` / `android` 本期不提供扫码地址。飞书扫码仍不实现。
2. **小时与分钟间隔。** 在 calendar schemaVersion 1 增加 `EVERY_N_HOURS` 与 `EVERY_N_MINUTES`。锚点是 `startDate` + `localTime`，按固定间隔前进，不随实际执行漂移。`intervalHours` 为 1—168，`intervalMinutes` 为 1—1440。原五种规则的发生结果不变。
3. **窗口。** 这两种规则在 7 天视野内可能超过同步事务 100 次发生的上限。同步创建、修改和恢复写入该视野内最早的至多 100 次；其余由 Planner（后台规划）按每轮至多 100 次补齐，仍不超过 7 天视野。原五种规则仍在一笔事务中写完整个 7 天窗口。
4. **稍后。** 由这两种规则物化的 [S02](../scenarios/S02-recurring-todo.md) 实例不支持稍后。实例快照记录 `snoozeAllowed=false`。HTTP 稍后命令拒绝。飞书卡片不提供「稍后提醒」按钮；入站若仍提交稍后，与 HTTP 一样拒绝。完成、跳过和催办间隔保持。日及以上规则的稍后行为不变。

## 5. 明确不做

- 飞书、钉钉或其他扫码登录。
- 每年、季度、月末，以及 [C01](../09-SCENARIO-ROADMAP.md)（扩展周期）的其余部分。
- 放宽 100 次同步发生上限，或改变原五种规则的 7 天整窗写入。
- 为小时和分钟间隔关闭催办。
- 把微信应用密钥写入仓库。

## 6. 影响

- 不修改 kernel 业务语义、平台公共表和 INV-01—INV-09。
- 身份专有表增加 oauth state。日历规则仍放在触发配置 JSON，不改公共表。
- 公开 API 增加两种日历类型，并让 [E25](../04-API.md) 在 `live` 模式下返回真实扫码地址。原五种类型的字段和发生结果不变。

## 7. 回滚

停止装配 `live` 即回到捕获或关闭。新日历类型拒绝写入后，已存在的小时/分钟定义需由调用方暂停或退役；不回写已发布的 P01—P06 标签。
