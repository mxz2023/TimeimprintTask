# P08 · 站内信实时提示

本阶段让已登录的工作台在不刷新页面的情况下得知站内信变化。浏览器先打开一条不结束的 HTTP 响应，服务端把心跳和变化写进这条响应。决策与字段以 [04](../../04-API.md) 的 [E30](../../04-API.md) 为准。不新增场景，不改站内信的写入、已读和表结构。

## 2. 已接受口径

| 口径 | 结论 |
| --- | --- |
| 方向 | 浏览器请求 `GET /api/v1/inbox/events`。服务端不主动连接浏览器 |
| 鉴权 | 与 [E10](../../04-API.md)—[E13](../../04-API.md) 相同，使用 `Authorization: Bearer`。无令牌或令牌无效时 401，且不开始事件流 |
| 事件 | 只提示变化：`unreadCount`、`latestInboxId`、`asOf`。正文仍由 E10 读取 |
| 唤醒 | 本进程在收件事务提交之后通知该接收人的连接。推送失败不回滚收件 |
| 另一进程 | 打开的连接至多每 5 秒按该接收人的水位核对一次。不引入消息队列或缓存 |
| 无连接 | 不排队。下次打开工作台重连后先读 [E12](../../04-API.md) |
| 心跳 | 每 25 秒写一行 SSE 注释。注释不是新站内信 |
| 超时 | 代理读超时保持 120 秒。单条连接最长 30 分钟，到点结束响应 |
| 已读 | 仍走 E13。首次已读提交后，该接收人已打开的连接也会收到变化事件 |
| 内核与表 | 不改 kernel 语义，不改 `tt_inbox` 及平台公共表 |

## 3. 允许与禁止

允许：

- 在 `timeimprint-task-web` 增加 E30，并在收件提交成功后通知同进程订阅者。
- 网页工作台在打开期间保持这条连接；收件箱分区打开时再拉 E10，其他分区只更新未读数。
- 仅为该路径关闭反向代理缓冲。本地与生产 Nginx 配置一起改。
- 验收范围是 [R01](../../07-ACCEPTANCE.md)—[R04](../../07-ACCEPTANCE.md)。

禁止：

- 改写已 RELEASED 的 P01—P07。
- 修改 kernel 业务语义、平台公共表或 E10—E13 的字段语义。
- 用浏览器原生 `EventSource` 代替带 Bearer 的 `fetch`。原生接口带不上现有令牌。
- 把完整收件列表放进事件流，或在没有连接时保存待投递队列。
- 为了长连接引入消息队列、缓存，或放宽整段 `/api/v1/` 的 120 秒读超时。
- 在用户确认本草案并明确授权实施之前写代码。

## 4. 必要人工步骤

自动测试可以证明事件流和未读数。下面这项要由人在真实页面上完成；做完并说明看到的结果之前，不得把本阶段标为 RELEASED。

1. 登录网页并停在任务工作台，不刷新页面。等到一条真实提醒写入站内信后，未读点自行变化；打开收件箱能看到这条新信。

## 5. 不变量

本阶段不改变 [INV-01](../../02-AI-CODING-GUIDE.md)—[INV-09](../../02-AI-CODING-GUIDE.md)。站内信仍在 Action 结果事务中写入；E30 只在事务提交之后向已经打开的响应追加字节。
